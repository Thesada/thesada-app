## Before you upgrade

- `THESADA_BASE_URL` must be an absolute URL with scheme and host (`https://app.example.com`). A relative value now stops the app at boot.
- Devices need firmware 1.4.5 or later, the first that echoes the request id. Every CalVer firmware (26.x) qualifies. File saves and rule pushes to older or unknown firmware are refused with a 409, and drift pulls skip them. A `config.json` save that leaves a secret field empty also needs `secret.info` on the device, which firmware 26.07.1 and later answer. Older firmware gets that save refused, nothing is sent.
- Self-host: `deploy/startup.sh` needs Docker Compose 2.17 or newer and stops on an older one.
- Rolling back to 26.11.4 needs no SQL. See "Roll back the app" in `docs/runbook.md` for what 26.11.4 does with data this release wrote.

## After you upgrade

- Run `thesada-app migrate-legacy-wifi` once. It moves each device's legacy `wifi.password` to the primary SSID of its stored config. A device's next config read does the same for that device, until then its legacy password is not provisioned. It is safe to run again. Its done line counts `no_ssid` and `undecryptable` rows, which stay inert. A `no_ssid` row moves on a later config read that names a primary SSID. An `undecryptable` row never moves: set that device's WiFi password again.

## What changed

| Area | Change |
|---|---|
| Sign-in | Passkeys as a second factor next to TOTP. The relying party comes from `THESADA_BASE_URL`, override it with `THESADA_WEBAUTHN_RP_ID` and `THESADA_WEBAUTHN_ORIGINS` |
| Alerts | Notification channels: one "Add channel" flow for email, Telegram and webhook. The upgrade turns the account email, the Telegram chat id and webhook URLs into channels. The account email channel follows the account address |
| Alerts | A new or changed email channel address gets a confirmation link and receives no alert mail until it is confirmed |
| Alerts | Trend rules: alert on a rise or fall of a metric over a window, set on the alerts page. At most 50 per tenant (`THESADA_QUOTA_TREND_RULES`, 0 turns the cap off). Device owners, tenant admins and operators edit them, viewers see them read-only |
| Alerts | Pairing a device into a tenant with no alert subscription subscribes one user to its account email at warn. The devices and alerts pages say when nobody in a tenant gets alerts |
| Rules | Tenant rules editor with Blockly blocks at `/devices/{id}/rules`. The app generates the Lua and pushes it. An operator save over a slot the tenant editor wrote asks for a takeover first |
| Devices | A `config.json` save that would erase a secret the device holds, or that is not one JSON object, is refused before anything is sent. Secrets read from a device config are kept in the encrypted store, open WiFi networks are allowed |
| Devices | Clear on device refuses a WiFi password that comes from a tenant default |
| Web | The footer shows the build version. Settings says alert rules stay in your home tenant while you view another one. A page error answers a clean 500 |
| Self-host | The compose file pins this release. `deploy/startup.sh` creates the timescaledb extension when it is missing and updates it before the migrations |
| Database | Migrations 0042 to 0049. `thesada-app migrate` applies them, the app does not on start. `deploy/startup.sh` runs it first |
